# Deployment handoff

The dashboard and API run in one Python process, with one concurrent inference task. No separate frontend host is required. This is an initial single-instance deployment; do not add multiple processes or replicas without replacing the in-process capacity gate and local SQLite storage with a shared queue and database.

## Delivery pipeline

`.github/workflows/ci-cd.yml` runs on pull requests, pushes to main and manual dispatch:

1. Validate syntax, 3,823 model/data checksums, feature mappings, request generation and API integration tests.
2. Build a Linux CPU-only Docker image and exercise actual model loading and LSTM/SVR forward passes for all three horizons. Run a complete seven-day forecast with SHAP under a 512 MB container limit. This verifies execution, not forecast accuracy or complete monthly/yearly forecasts.
3. On main only, publish the verified image to `ghcr.io/winnie-bunny/jining-coal-price-prediction`, tagged with the full commit SHA and `latest`. Repository settings must allow Actions to publish packages. Package access is not changed by this workflow.
4. If repository variable `RENDER_DEPLOY_ENABLED` is `true`, call the secret `RENDER_DEPLOY_HOOK_URL` with the verified commit SHA. The production environment can apply deployment approval rules if the owner configures them.

The provided Render Blueprint uses Git-based Docker builds: Render rebuilds that verified commit instead of pulling from GHCR, avoiding a second private-registry credential. The GHCR image remains available for other hosts. Consequently the running image is built from the same commit, but is not guaranteed to have the identical digest. To deploy the exact GHCR image instead, create an image-backed Render service with private registry credentials and change the hook to use `imgURL` with the SHA tag.

A successful hook request only means a deployment was requested. Check Render's deployment status and `/health` before declaring a rollout complete. Automatic Render deployments are disabled to prevent a push bypassing CI.

## Account configuration still required

- GitHub write access to the existing repository and permission to publish Actions workflows.
- Render account linked to this repository.
- `deploy/render.yaml` is a free trial without durable storage. Its 512 MB memory limit may be insufficient for PyTorch and all three model bundles; actual startup must be verified. State can be lost on restart/redeploy. `deploy/render-paid.yaml` is a separate draft with 1 CPU / 2 GB RAM and a 1 GB persistent disk: review and approve current charges before applying it. Actual resource requirements must be measured with real workloads.
- Create a Blueprint with path `deploy/render.yaml` after the verified commit is on main. Initial service creation may deploy immediately, so check CI before creation.
- Copy the Render deploy hook into the GitHub Actions secret `RENDER_DEPLOY_HOOK_URL`; set variable `RENDER_DEPLOY_ENABLED=true` only when the service is ready.
- Keep `API_KEY` in Render environment secrets. It is generated by the Blueprint; do not commit it or expose it in logs. Share it only with authorized users through a secure channel.

No cloud resources have been created by adding these files. GitHub Actions billing and Render compute/storage depend on the account and selected plan.

## Runtime

- `/`: Chinese dashboard. Upload an API-format JSON request; select a matching forecast horizon; enter the API key; submit, poll and download results.
- `/health`: model readiness, public for health probes.
- `/tasks` and `/tasks/<id>`: Bearer API key required when `API_KEY` is configured.
- `REQUIRE_API_KEY=1`: refuse public server startup if the key is absent.
- `STATE_DIR`: SQLite task metadata and completed JSON results; mount durable storage here. Restarted in-flight jobs are marked failed and must be resubmitted. Completed jobs remain queryable.
- Request limit: 8 MB. One active inference at a time, otherwise HTTP 429.
- Annual requests require exactly 364 consecutive daily records; other periods require at least 60/90 daily records. Numeric fields must be finite numbers.
- Existing sample data ends in 2025 and is historical. It is not a live market feed.

Local setup (Python 3.11 recommended):

```bash
python -m pip install -r inference/requirements.txt
python inference/app.py
```

Open `http://127.0.0.1:7020`. Generate request files with `project_materials_2026-10-16/scripts/make_request.py`. The dashboard takes JSON; raw CSV conversion is provided by this generator, not by the upload control.

## Free-instance explanation memory

The first live weekly request exceeded the free instance's 512 MB limit during default Kernel SHAP allocation (confirmed by Render's OOM event). Forecast prices had already been computed. The factor analysis now uses at most 16 evenly spaced background records and 256 mask samples per forecast day. This reduces the synthetic input matrix from roughly 400 MB to roughly 7 MB for 212 features; total process memory is larger. These limits change approximate factor attribution values, not LSTM/SVR prices. Configure SHAP_BACKGROUND_LIMIT (1..95) and SHAP_NSAMPLES (1..4096) for larger instances. Higher limits require more memory. The dashboard labels these values as estimates.
